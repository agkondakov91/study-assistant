# 🧩 Этап 2. Материал как объект

**После лекции 9** «Классы и объекты»
**Проверка:** `uv run pytest -m stage2`

---

## 🎯 Что делаем и зачем

На первом этапе характеристики файла лежали в словаре:

```python
{"file": "functions.md", "title": "Функции", "lines": 3, "words": 15, "chars": 112}
```

Работает — но у такого решения три слабых места.

**Опечатка находится поздно.** `item["titel"]` упадёт не при написании кода,
а когда программа дойдёт до этой строки.

**Непонятно, что внутри.** Открыв функцию, принимающую словарь, вы не знаете,
какие у него ключи. Приходится искать место, где он создаётся.

**Данные отдельно, действия отдельно.** Функция «пустой ли материал» лежит
где-то ещё, и связь между ней и словарём существует только в голове
программиста.

Класс решает все три: состав полей описан в одном месте, редактор подсказывает
имена, а методы лежат рядом с данными.

## 📦 Что меняется в проекте

Новых файлов создавать не нужно — вы работаете в тех же файлах, что и раньше.

| Файл | Что с ним делаем |

| `study_assistant/material.py` | Заготовка класса уже лежит — дописываем пять методов |

## 📝 Задание

> ⚠️ **Вывод программы не должен измениться ни на символ.** Меняется внутреннее
> устройство, а не поведение. За этим следит `tests/test_contract.py` — файл,
> который живёт весь курс и не меняется никогда.
>

> фиксируем поведение, потом меняем код.

### 1. Класс `Material`

Пять методов. Имена класса, методов и атрибутов менять нельзя — по ним написаны
тесты.

| Метод | Что делает |
|---|---|
| `__init__(self, file, title, lines, words, chars)` | Сохраняет пять значений как атрибуты с теми же именами |
| `is_empty(self)` | Возвращает `True`, если `lines` равно нулю |
| `summary(self)` | Возвращает `"строк: 3, слов: 15, символов: 112"` |
| `to_dict(self)` | Возвращает словарь с пятью ключами — теми же, что на этапе 1 |
| `__repr__(self)` | Возвращает `"Material('functions.md', слов=15)"` |

Константу `EMPTY_TITLE` перенесите сюда из `catalog.py` — она относится
к материалу, а не к каталогу. В `catalog.py` замените её объявление на импорт:

```python
from study_assistant.material import EMPTY_TITLE, Material
```

Отдельный тест проверяет, что константа переехала.

> 💡 **Про `self`.** Это сам объект, для которого вызван метод. Python
> подставляет его автоматически, при вызове передавать не нужно.
>
> Без `self.` перед именем атрибут не создастся — вместо него появится локальная
> переменная, и ошибка вылезет позже, при обращении. Тест на этот случай выдаёт
> подсказку прямым текстом.

> 💡 **Про `__repr__` и `!r`.** Суффикс `!r` в f-строке показывает строку
> в кавычках: `{self.file!r}` даёт `'functions.md'`, а не `functions.md`.
> В `__repr__` так принято — сразу видно, что значение строковое.
>
> Без `__repr__` объект печатается как `<...Material object at 0x104a3e510>`,
> и отладить список таких объектов невозможно.

### 2. Три функции в `catalog.py`

Функции уже написаны — вы делали их на этапе 1. Переделать нужно три.

| Функция | Что поменять |
|---|---|
| `read_material(path)` | Вместо словаря вернуть объект `Material` |
| `save_catalog(catalog, path)` | Перед записью превратить объекты в словари через `to_dict()` |
| `print_report(catalog)` | Работать с атрибутами объектов вместо ключей словаря |

Функции `build_catalog` и `load_catalog` **менять не нужно**:

- `build_catalog` просто складывает в список то, что вернула `read_material`, — а что именно, ей неважно;
- `load_catalog` возвращает сырые словари, прочитанные из файла, и это правильный для них тип.

> 💡 **Ошибка, которую вы почти наверняка увидите.** Если забыть про `to_dict()`,
> программа упадёт с `TypeError: Object of type Material is not JSON serializable`.
> Это не баг: модуль `json` знает шесть типов, и `Material` среди них нет.
>
> Здесь важна общая мысль: **сырые структуры данных живут на границах программы,
> а внутри работают типы.** Словарь появляется только в момент записи в файл.

> 💡 **В `print_report` не собирайте строку со счётчиками заново** — у материала
> для этого есть готовый `summary()`. Отдельный тест проверяет, что метод
> действительно вызван.

### 3. Поправьте тесты этапа 1

Часть тестов в `tests/test_stage_01_catalog.py` написана под словари. Когда
`read_material` начнёт возвращать объект, они перестанут соответствовать
действительности.

Это **нормальная инженерная ситуация**: изменился контракт функции — изменились
тесты. Ваша задача — привести их в соответствие, а не закомментировать.

Конкретно: обращения вида `result["title"]` меняются на `result.title`.

> 💡 Это одна из причин, по которой тесты пишут: они показывают, какие места
> программы затронет изменение. Без них пришлось бы искать вручную.

### Проверьте объект руками

Создайте `try.py` в корне проекта:

```python
from pathlib import Path

from study_assistant.catalog import read_material

material = read_material(Path("materials/functions.md"))

print(repr(material))
print(material.title)
print(material.is_empty())
print(material.summary())
print(material.to_dict())
```

Должно получиться:

```
Material('functions.md', слов=15)
Функции
False
строк: 3, слов: 15, символов: 112
{'file': 'functions.md', 'title': 'Функции', 'lines': 3, 'words': 15, 'chars': 112}
```
