# 🔌 Этап 3. Источник материалов

**После лекции 11** «Инкапсуляция и абстракция»
**Проверка:** `uv run pytest -m stage3`

---

## 🎯 Что делаем и зачем

Сейчас программа жёстко знает, откуда брать материалы: из папки `materials`.
Строчка в `main.py` вызывает `build_catalog(MATERIALS_DIR)` — и всё.

Пока конспекты лежат в папке рядом, это нормально. Но дальше по курсу
материалы придут ещё откуда-нибудь: из сохранённого каталога, из выгрузки
с сервера, из базы данных. И тогда вопрос: сколько мест в программе придётся
переписать?

Ответ зависит от того, что именно знает окружающий код. Если он знает
**«материалы лежат в папке»** — переписывать придётся всё. Если он знает
**«есть источник, у него можно попросить список материалов»** — не придётся
ничего: достаточно подставить другой источник.

Это и есть задача этапа: заменить знание о способе на знание о контракте.

> 💡 Через несколько занятий ровно так же появится подменяемый клиент языковой
> модели: локальная Ollama или облачный сервис. Код вокруг не должен замечать
> разницы. Тренируемся на источнике — он проще.

## 📝 Задание

### 1. Контракт `MaterialSource`

Он **уже написан** в заготовке — читать, но не менять:

```python
class MaterialSource(ABC):
    @property
    @abstractmethod
    def description(self):
        """Возвращает описание источника для отчёта, строка."""

    @abstractmethod
    def load(self):
        """Возвращает список объектов Material."""
```

Здесь нет ни строчки работающего кода — только требования. Проверьте это
руками, до того как писать остальное:

```python
from study_assistant.source import MaterialSource

MaterialSource()
```

```
TypeError: Can't instantiate abstract class MaterialSource
without an implementation for abstract methods 'description', 'load'
```

Питон не даёт создать объект, потому что пользоваться таким объектом
невозможно: методы объявлены, но не написаны. Ошибка приходит **сразу при
создании**, а не через сто строк при первом вызове.

### 2. `FolderSource` — материалы из папки

| Метод | Что делает |
|---|---|
| `__init__(self, directory)` | Сохраняет путь в `self._directory`, обернув в `Path(...)` |
| `description` | Возвращает `"папка materials"` |
| `load(self)` | Возвращает `build_catalog(self._directory)` |

Да, `load` — **одна строка**. В лекции мы писали здесь цикл по `glob` целиком,
чтобы увидеть устройство источника от начала до конца. Но в проекте такой цикл
уже есть — это `build_catalog` с первого этапа. Копировать его во второе место
не нужно: две копии одного кода расходятся при первой же правке.

Источник не переписывает старый код, он **даёт ему новое лицо**.

### 3. `JsonSource` — материалы из файла каталога

| Метод | Что делает |
|---|---|
| `__init__(self, path)` | Сохраняет путь в `self._path`, обернув в `Path(...)` |
| `description` | Возвращает `"файл catalog.json"` |
| `load(self)` | Читает файл через `load_catalog` и превращает каждый словарь в объект |

```python
Material(**item)
```

Две звёздочки разворачивают словарь в именованные аргументы. Работает это
потому, что ключи словаря совпадают с именами параметров `__init__`, —
а совпадают они потому, что словарь собрал ваш же `to_dict()`.

> 💡 `to_dict()` и распаковка `**` образуют пару: одно превращает объект
> в словарь для записи в файл, другое — словарь обратно в объект при чтении.
> Сырые структуры живут на границе программы, внутри работают типы.

### 4. `main.py` — выбор источника в одном месте

Перепишите точку входа так, чтобы источник выбирался **одной строкой**:

```python
SOURCE = FolderSource(MATERIALS_DIR)
```

Дальше программа работает только с `SOURCE`: спрашивает `SOURCE.description`
для заголовка и `SOURCE.load()` для материалов. Слова `build_catalog`
в `main.py` больше быть не должно.

Ловить нужно две ошибки: `FileNotFoundError` (нет папки или файла) и
`json.JSONDecodeError` (файл каталога повреждён). Обе приходят из `load()` —
какая именно, зависит от подставленного источника, и это уже не забота
точки входа.

### Главный эксперимент этапа

Он важнее тестов — ради него всё и делалось.

**Шаг 1.** Запустите программу как есть:

```bash
uv run main.py
```

Первая строка — `Источник: папка materials`. Заодно создастся `catalog.json`.

**Шаг 2.** Поменяйте в `main.py` одну строку:

```python
SOURCE = JsonSource(CATALOG_FILE)
```

(и поправьте импорт).

**Шаг 3.** Запустите снова.

Первая строка изменится на `Источник: файл catalog.json`. **Всё остальное —
ни на символ.** Программа прочитала данные совершенно другим способом, а отчёт
получился тот же, потому что `print_report` не знает и не хочет знать,
откуда пришёл список.

Сравните вывод машинно, чтобы не доверять глазам:

```bash
uv run main.py > out_folder.txt
# поменяйте строку SOURCE
uv run main.py > out_json.txt
diff out_folder.txt out_json.txt
```

Различаться должна ровно одна строка — та, что называет источник.

**Шаг 4.** Верните `FolderSource` — с ним программа работает и на чистой копии,
где `catalog.json` ещё нет.

### Проверьте контракт руками

Создайте `try.py` в корне:

```python
from study_assistant.source import MaterialSource


class EmptySource(MaterialSource):
    """Источник, который забыли дописать."""

    def load(self):
        """Возвращает пустой список."""
        return []


EmptySource()
```

```
TypeError: Can't instantiate abstract class EmptySource
without an implementation for abstract method 'description'
```

Питон назвал ровно то, чего не хватает. Допишите `description` — ошибка уйдёт.
Это и значит «контракт»: список обязательств проверяется автоматически.

## ⚠️ Типичные ошибки

| Что происходит | В чём дело |
|---|---|
| `description вернул method вместо строки` | Забыт декоратор `@property` — обращение стало вызовом метода |
| `'str' object has no attribute 'exists'` | Забыт `Path(...)` в конструкторе: пришла строка, а `.glob()` есть только у `Path` |
| `'dict' object has no attribute 'file'` | `JsonSource.load` вернул словари — забыт `Material(**item)` |
| `FolderSource должен наследоваться от MaterialSource` | В скобках после имени класса пусто |
| `Can't instantiate abstract class ...` на своём классе | Реализованы не все обязательные методы — Python назовёт какие |

> 💡 Не пытайтесь «обойти» абстрактный класс. Если Python не даёт создать
> объект — он прав: пользоваться таким объектом всё равно нельзя, ошибка
> просто пришла бы позже и в менее понятном месте.

### 🎁 Дополнительно (+1 балл)

Добавьте третью реализацию — `EmptySource`: источник без материалов.
`load()` возвращает пустой список, `description` — `"пустой источник"`.

Подставьте его в `main.py` и посмотрите, что напечатает программа. Должно
получиться `Файлов в каталоге: 0` и `Всего слов во всех материалах: 0`.

Скорее всего, ничего исправлять не придётся: цикл по пустому списку просто
не сделает ни одного шага, а `sum([])` равен нулю. Но если у вас
`print_report` падает — чините её, а не источник: пустой список это законные
данные, а не ошибка. После правки `test_contract.py` должен остаться зелёным.

В описании PR напишите, сколько строк кода понадобилось, чтобы добавить
в программу третий способ получать материалы.
